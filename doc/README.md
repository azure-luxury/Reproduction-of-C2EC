# 一种基于大语言模型、无需训练的通用中文字符错误纠正方法
## 摘要
中文拼写纠错（Chinese Spelling Correction, CSC）是一项重要任务，旨在纠正中文文本中的字符错误。传统 CSC 主要关注由误输入导致的字符替换错误，而另外两类常见的字符错误——缺字和多字——受到的关注较少。这类错误在 CSC 数据集的标注过程中常常被排除；即使已经被标注，在评估时也经常被忽略。这一问题限制了 CSC 任务的实际应用价值。为了解决这一问题，本文提出了通用中文字符错误纠正任务（General Chinese Character Error Correction, C2EC），该任务同时关注上述三类字符错误。我们通过整合 CCTC 和 Lemon 数据集，并进行人工核验，构建了一个高质量的C2EC 基准数据集。我们将一种无需训练、无需提示词的 CSC 方法扩展到 C2EC 任务中：使用 Levenshtein 距离来处理文本长度变化，并引入额外的基于提示词的大语言模型（LLM）以提升性能。实验表明，在无需任何微调的情况下，我们的方法使一个 140 亿参数的大语言模型在传统 CSC 和 C2EC 任务上都能达到与参数规模接近其 50 倍的模型相当的效果。

### 1引言
给定一个输入句子 x = x1, x2 ··· xn，传统中文拼写纠错（CSC）任务的目标是生成一个长度相同的新句子，记为 y = y1, y2 ··· yn，其中每个拼写错误的字符，例如 xi，都会被替换为正确字符，例如 yi。文本中的拼写错误可能造成误解，损害文本的真实性，甚至导致不必要的经济损失，因此自动纠错是中文自然语言处理（NLP）中的一项关键任务。
拼写错误主要来源于两个方面。第一类来源是输入错误。中文汉字往往存在多个字形相近或读音相近的变体，因此在使用输入法时很容易选择错误的字符。第二类来源是自动文本转换错误。在使用自动语音识别（ASR）或光学字符识别（OCR）时，系统在转换过程中也可能引入错误字符。
除拼写错误之外，涉及缺字和多字的字符错误也很常见。这些错误可能由与拼写错误相同的原因造成。例如，在输入“醋酸曲安奈德”（Triamcinolone Acetonide）中的“曲安”（qū ān）时，输入法可能会将“qū ān”误识别为单个汉字“圈”（quān），从而同时产生错字和缺字错误。此外，反复编辑句子也容易引入缺字和多字错误，例如修改消息、社交媒体帖子或电子邮件时。例如：“我参加的项目是羽球。”（英文含义近似为：The project I participated in is badmton），其中“羽毛球”（badminton）中的“毛”被遗漏了。缺失的“毛”很可能是在编辑过程中产生的：用户在将误输入的“求”改为“球”时，可能不小心删除了前面的两个字符，然后重新输入“球”。如果不仔细校对，这类错误往往不容易被发现。为了表述清晰，本文将错字、缺字和多字错误统称为通用中文字符错误（General Chinese Character Errors, C2E）。
近年来的中文文本纠错比赛，如 CTC 2021、Midu-CTC 和 Kingsoft-CTC，都设计了更贴近真实场景的错误分布。在这些比赛中，C2E 占全部错误的 79.4% 到 87.3%。这表明，与语法错误、逻辑不一致或歧义等复杂错误相比，C2E 更为常见。与传统 CSC 相比，处理 C2E 更具有实际意义，因为它覆盖了范围更广的常见错误类型。
因此，我们认为，通用中文字符错误纠正（C2EC）应当得到中文文本纠错研究领域更多的关注。虽然 He 等人（2023）此前也研究过 C2EC，但他们是通过在正确句子中随机加入错误的方式构造了合成数据集 ECMR-2023。目前仍缺少一个专门关注真实场景中 C2E 错误的数据集。
为填补这一空白，我们基于两个包含真实错误的已有数据集 CCTC 和 Lemon，构建了一个新的 C2EC 数据集。我们对数据进行了细致核验，以确保数据质量和标注一致性，最终得到 1,995 条开发集句子和 5,711 条测试集句子。
近期研究已经展示了大语言模型（LLM）在 CSC 任务中的能力。尤其是，训练无关、提示词无关框架（TfPf）通过结合用于评估流畅性的大语言模型和用于防止过度纠错的 Hamming 距离，在无需任何训练的情况下取得了较强效果。我们将该方法扩展到 C2EC 任务中：使用 Levenshtein 距离来处理缺字和多字错误，并引入基于提示词的概率评分以进一步提升性能。
实验表明，我们的方法在传统 CSC 数据集和 C2EC 数据集上相较 TfPf 基线都有显著提升，并且在多个领域中甚至超过了监督微调方法。
还值得指出的是，我们的方法使一个 140 亿参数模型在无需任何训练的情况下，能够达到与近 50 倍参数规模模型相当的性能。
我们的代码发布在：https://github.com/Jacob-Zhou/simple-csc/tree/v2.0.0。

### 2 C2EC 任务
2.1任务定义
给定一个输入句子 x = x1, x2 ··· xn，C2EC 任务的目标是纠正其中的字符错误，并生成纠正后的句子 y = y1, y2 ··· ym。与输入和输出长度必须一致的传统 CSC 不同，C2EC 允许输出句子 y 与输入句子 x 的长度不同。除字符替换错误之外，C2EC 还处理另外两类错误：a）缺字：即输入中遗漏了某些字符，例如“羽球”相对于“羽毛球”（badminton）缺少了“毛”。b）多字：即输入中出现了不应存在的额外字符，例如“羽矛毛球”中多出的“矛”。

2.2数据集构建
与 He 等人（2023）采用基于规则的合成方式不同，我们从已有数据集中构建数据集，以更好地反映真实世界中的错误模式。
数据选择与划分：我们从两个高质量来源构建 C2EC 数据集。a）CCTC：这是一个包含约 25,000 个句子的综合性数据集，数据来源多样，覆盖字符错误和复杂错误。尽管该数据集包含 C2E 错误，但它并不是专门为 C2EC 任务设计的。b）Lemon：这是一个 CSC 数据集，其中包含约 500 条带有缺字和多字错误的句子。虽然该数据集中包含 C2E 错误句子，但以往研究在评估 CSC 方法时通常会排除这些句子。我们使用 CCTC 的训练集作为开发集，并将 CCTC 和 Lemon 的测试集合并作为测试集。
数据重采样：为了获得更加平衡且自然的错误分布，我们进行了两步重采样。a）我们将正确句子与错误句子的比例调整为 1:1，从而减轻 CCTC 原本 91% 句子为正确句子的偏置。b）我们调整 Lemon 的错误类型分布，使其与 CCTC 中约 75% 为替换错误、约 25% 为缺字/多字错误的分布相匹配，从而缓解 Lemon 中替换错误占比高达 95% 的偏置。在整个重采样过程中，我们保持不同领域之间以及正确—错误句对之间的分布平衡。
质量控制：为了使数据集聚焦于字符级错误并保持数据清洁，我们采用了两种数据清洗流程。a）自动移除包含复杂错误的句子，尤其是涉及连续插入或连续删除的错误。该步骤分别从开发集和测试集中移除了 91 条和 90 条句子。b）由中文母语者对句子进行人工核验，移除以下句子：i. 标注错误的句子；ii. 包含复杂语法错误的句子；iii. 存在多个合理纠正结果的句子；iv. 存在歧义或难以理解的句子。四名熟悉 CSC 任务的中文母语者参与了人工核验。每个句子至少由两名标注者审核；如存在分歧，则由第三名标注者进行裁决。标注者之间的一致率达到 97.08%。该过程从测试集中移除了 111 条句子，从开发集中移除了 31 条句子。

2.3 Data Statistics / 数据统计
如表 1 所示，最终数据集包含 1,995 条开发集句子和 5,711 条测试集句子，其中约一半句子不含错误。开发集中包含 1,098 个错误，平均每个错误句约 1.1 个错误；测试集中包含 3,301 个错误，平均每个错误句约 1.2 个错误。在测试集中，72.6% 的错误为错字错误，14.0% 为多字错误，13.4% 为缺字错误。

### 3 The Baseline TfPf Approach / 基线 TfPf 方法
训练无关、提示词无关框架（TfPf）（Zhou et al., 2024）将大语言模型与一个距离度量结合起来，其评分函数为：s(x, y) = log pLLM(y) - Dist(x, y)。其中，第一项 pLLM(y) 表示大语言模型对候选正确句子 y 的概率建模，用于从语言角度保证纠正结果的流畅性；第二项 Dist(x, y) 用于度量输入句子 x 与输出句子 y 之间的 Hamming 距离，从而防止模型为了追求流畅性而对输入句子进行过多修改，或随意插入、删除字符。

### 4 我们用于 C2EC 的无训练方法
我们在 TfPf 框架基础上进行扩展，提出新的评分函数：s(x, y) = log pLLM(y | Prompt(x)) + log pLLM(y) - DistL(x, y)。其中 Prompt(·) 表示提示词模板。该方法对 TfPf 做了三点关键扩展：第一，允许输入句子 x 和输出句子 y 的长度不同；第二，将原本的 Hamming 距离替换为 Levenshtein 距离，以处理输入和输出长度不一致的问题，并用 DistL 与原始距离度量 Dist 区分；第三，在评分函数中加入额外的基于提示词的概率项 pLLM(y | Prompt(x))，以进一步提升纠错性能。

4.1 用于生成的增量加权 Levenshtein 距离
沿用 TfPf 的思路，我们使用加权距离度量来衡量输入句子 x 和输出句子 y 之间的差异。我们将不同编辑操作划分为不同类型，并为每一类操作分配特定权重。表 2 给出了本文使用的权重：保留操作权重为 0.04；替换操作根据相似性分为同拼音、近似拼音、近似字形和其他相似情况，权重分别为 3.75、4.85、5.40 和 8.91；新增的插入和删除操作权重分别为 8.50 和 9.00。对于 TfPf 中已有的操作类型，我们沿用原始权重；对于插入和删除这两类新操作，则通过开发集上的网格搜索确定权重。

由于大语言模型是逐步生成输出的，而 Levenshtein 距离通常需要在整个句子范围内通过动态规划计算，这两者存在不兼容。为缓解这一问题，我们引入了增量 Levenshtein 距离。对于一个部分输出候选 y≤j，我们将部分距离定义为 y≤j 与输入句子相应前缀 x≤b 之间的 Levenshtein 距离。生成新字符 yj 之后，增量距离等于新前缀距离与旧前缀距离之差；其中符号 ∘ 表示拼接，a 和 b 分别表示生成 yj 前后输入前缀的结束位置。

4.2 额外使用基于提示词的 LLM
从强化学习角度看，公式 2 中使用两个 LLM 的方式可以理解为：TfPf 框架充当一个奖励函数，用来引导生成过程；基于提示词的 LLM 相当于参考模型，根据提示词给出纠错概率；而纯语言模型则负责评估生成序列本身的流畅性。
为了节省 GPU 显存，我们在基于提示词的 LLM 和纯语言模型函数中使用同一个模型；如果显存充足，也可以为这两个功能分别使用不同模型。我们选择 LLM 的 Base 版本同时用于提示词模型和语言模型，因为实验显示，相比指令微调版本，Base 版本在不同提示模板下更加稳健，并且整体性能更好。

在提示词模板方面，我们设计了两类模板：一种是基于 Li et al.（2024）的最简提示词（Minimal），另一种是基于 Li et al.（2023）和 Zhou et al.（2024）的更复杂提示词（Detailed）。图 2 展示了最简提示词，它只包含必要的任务描述和输入句子，例如要求模型“纠正下面句子中的错别字以及多字少字错误，并给出修改后的句子”。详细提示词则额外包含任务专用系统提示、格式要求和注意事项。实验结果表明，Base 版本 LLM 更适合最简提示词，而指令微调 LLM 更适合详细提示词；综合性能考虑，我们最终采用最简提示词。

4.3 基于 token 的生成与束搜索
大语言模型在处理中文时通常使用多字符 token，一个 token tk 可能包含多个汉字。为方便描述，我们将第 k 步生成时的部分输出候选定义为 y≤j = y1 ... yj = t1 ... tk。在每一步生成中，模型计算当前 token 的得分：得分由三部分组成，即基于提示词的 LLM 概率、纯语言模型概率，以及生成该 token 后产生的增量 Levenshtein 距离惩罚。
我们使用束搜索（beam search）来寻找最终输出。具体来说，在每个生成步骤 k，模型会扩展所有可能的 token tk 和输入前缀结束位置 b，然后只保留得分最高的前 K 个候选。沿用 TfPf 的设置，本文将束大小设为 8。

4.4 完整模型

在完整模型中，我们继续沿用 TfPf 的长度奖励和忠实性奖励，并将它们加入最终评分函数。忠实性奖励 λ = 1 +HLLM(·) 的作用是：当语言模型不确定时，动态增大距离项的影响，从而让模型更谨慎地偏离原句。长度奖励 α(len(tk) – 1)则鼓励模型选择更长的 token，这有助于缓解中文多字符 token 生成时可能出现的偏差。

### 5 实验设置
5.1 数据集
我们在传统 CSC 数据集和新构建的 C2EC 数据集上同时评估方法。对于传统 CSC，按照 Li et al.（2024）的设置，我们使用两个代表性数据集：CSCD-NS 和 Lemon。二者都包含由中文母语者书写的文本，其中 CSCD-NS 主要用于评估通用领域表现，而 Lemon 用于评估零样本跨领域能力。由于我们无法获取 ECMR-2023 数据集，因此实验中没有包含该数据集。

5.2 评估指标
沿用已有研究，我们将字符级纠正 F1 作为主要评估指标。由于句子级指标在以往研究中也被广泛使用，因此我们还在附录 E.1 中报告了句子级结果；更详细的指标定义见附录 D.4。

5.3 基线方法
我们将我们的方法与三种无训练基线进行比较。第一种是上下文学习（ICL）：该方法为每个输入随机选择并打乱 10 个示例，其中 5 个为错误句子，5 个为正确句子，并在推理时使用与本文方法相同的束大小。第二种是训练无关、提示词无关方法 TfPf。第三种是带重排序的 ICL（ICL-RR）：该混合方法先使用 ICL 生成 K 个候选，然后用扩展后的 TfPf 模型进行重排序；该扩展模型支持插入和删除操作。
作为参考，我们还加入了若干通过 API 调用的领先 LLM 的 ICL 结果，包括 GPT-4o-mini、GPT-4o，以及 671B 参数规模的 DeepSeek V3 和 DeepSeek R1。此外，我们也加入了 Li et al.（2024）在传统 CSC 数据集上的监督微调结果，以帮助理解不同方法之间的差异。
对于监督微调基线，相关模型使用由 27.1 万个伪句对和 CSCD-NS 训练数据组成的混合数据集进行训练。这意味着 CSCD-NS 是域内评估数据，而 Lemon 则被用作跨领域数据集，用于考察模型的泛化能力。

5.4 模型选择
我们主要使用 Qwen2.5 系列模型进行实验，因为它是较新的开源大语言模型之一，并且具有较强的中文能力。对于 ICL 实验，我们使用适合指令跟随的 Instruct 版本；而对于本文方法，则使用 Base 版本。为了降低计算成本，详细分析主要使用 7B 版本。此外，为进一步验证方法有效性，我们还在讨论部分分析了 Qwen1.5、Baichuan2 和 InternLM2 这三个其他 LLM 系列。
5.5 超参数
我们大体沿用 Zhou et al.（2024）中的超参数设置：束大小设为 8，长度奖励参数 α 设为 2.5。经过开发集调参后，插入和删除操作的权重分别设为 8.5 和 9.0，基于提示词评分的 temperature 设为 1.5。在消融实验中，我们会针对每一种设置单独调整 temperature，以使对应 F1 分数最大化。

### 6 主要结果
如表 3 所示，我们提出的方法在传统 CSC 数据集和 C2EC 数据集上都优于 ICL、ICL-RR 和 TfPf。与其直接扩展来源 TfPf 相比，该方法在 7B 和 14B 模型上平均分别提升了 8.49 和 10.24。与 ICL-RR 相比，我们的方法被证明是结合“基于提示词的 LLM”和 TfPf 优势的更好方式，因为 ICL-RR 只能从 ICL 生成的 top-K 候选中重新排序；如果这些候选本身没有好的答案，那么重排序也无法改善最终结果。
与 Li et al.（2024）的监督微调模型相比，我们的方法在域外 Lemon 数据集上表现更好。这说明监督微调方法虽然在训练过的 CSCD-NS 这类域内数据上可能有优势，但在未见过的新数据上泛化能力不足。相比近期领先的大模型，例如 671B 参数的 DeepSeek V3，本文方法让 7B 和 14B 这类小得多的模型在无需训练的情况下也能达到相近表现。
另外一个值得注意的现象是，推理模型 DeepSeek R1 在 CSC 和 C2EC 任务上的表现反而低于其非推理版本 DeepSeek V3。我们认为这可能是由错误推理导致的，后文附录中对此有进一步讨论：推理模型有时会“想太多”，把原本正确但不常见的词误改为更常见的词，从而造成过度纠错。

### 7 讨论
7.1 Hamming 距离与 Levenshtein 距离
本文对 TfPf 的第一个扩展，是将原本的 Hamming 距离替换为 Levenshtein 距离，从而允许插入和删除操作。实验显示，在 C2EC 数据集上，使用 Levenshtein 距离的模型效果更好，因为 C2EC 需要处理缺字和多字问题；但在传统 CSC 数据集 CSCD-NS 上，Levenshtein 距离反而会降低效果。原因有两个：第一，传统 CSC 数据集只包含替换错误，任何插入或删除都可能造成过度纠错；第二，插入、删除操作可能与替换操作发生竞争，导致模型本该替换某个错字时，却错误地删除了该字符。

7.2 双 LLM 设计的有效性
第二个扩展是在 TfPf 框架中加入基于提示词的 LLM 概率。表 4 的消融实验显示，如果去掉这一项，模型在两个数据集上的精确率和召回率都会明显下降，说明基于提示词的 LLM 概率是本文方法的关键组成部分。一个自然的问题是：既然已经有了基于提示词的 LLM，为什么还需要纯 LLM 概率？实验显示，如果去掉纯 LLM 概率，CSCD-NS 和 C2EC 上的性能分别下降 11.10 和 5.45 分。我们解释说，纯 LLM 概率从普通语言模型角度评估句子的流畅性和正确性，因此能鼓励模型生成更自然、更正确的句子。
7.3 不同提示词模板的影响
我们在第 4.2 节中介绍了两类提示词：一种是最简提示词，另一种是包含更多指令的详细提示词。本节分析不同提示词模板的影响。表 4 的结果显示，Base 版本 LLM 更偏好最简提示词，而指令微调版本 LLM 更适合较长、较复杂的提示词。总体来看，相比指令微调模型，Base LLM 对提示词变化更加稳健。

7.4 LLM 规模的影响
为了研究模型规模的影响，我们在 Qwen2.5 系列的不同规模模型上进行了实验。结果表明，随着模型规模增大，本文方法的效果通常会提升。相比之下，TfPf 的表现并不会随着模型规模增大而稳定提升，这说明本文方法能更好地利用大模型规模带来的能力提升。不过，在 0.5B 这种非常小的模型上，由于模型对提示词的理解能力有限，TfPf 反而可能优于本文方法。

7.5 不同错误类型上的表现
图 4 展示了模型在 C2EC 开发集上对不同错误类型的表现，包括缺字（MIS）、多字（RED）和替换/错字（SUB）。结果显示，本文方法在所有错误类型上都优于基线方法。不同错误类型的难度并不相同：替换错误最容易纠正，因此所有方法在这一类上表现都相对较好；多字错误最困难，主要原因是模型容易在本来无错的句子中添加一些可选字符，从而造成过度纠错。

### 8 相关工作
8.1 中文拼写纠错数据集
中文拼写纠错长期以来都是 NLP 中的重要研究方向，研究者不断构建新的数据集来满足不同需求。Sighan 系列数据集是最早、也最有影响力的一批 CSC 数据集之一，但它们也常被批评存在标注质量较差、领域有限、错误模式不够真实等问题。后来一些研究尝试通过重新标注来改善 Sighan 数据集，但其领域和错误模式有限的问题仍然存在。为了解决这些问题，研究者开始在金融、公文、医疗等领域人工构造错误；也有工作从七个不同领域收集并标注真实错误，构建不提供训练数据、用于挑战模型泛化能力的大规模数据集。类似地，Hu et al.（2024）也基于社交媒体中的真实错误构建了新数据集。

8.2 用于中文拼写纠错的大语言模型
早期使用 LLM 进行 CSC 的尝试主要集中在提示词方法上。例如，有研究在提示词中加入读音和字形信息，以帮助模型识别相似音、相似形错误。然而，7B 或 14B 这类轻量级 LLM 仅靠提示词方法仍难以取得令人满意的效果。相比之下，监督微调方法通常更有效，其中代表性工作是 Li et al.（2024）提出的一种新训练范式，通过在字符层面对 LLM 重新训练，使其更好地适配 CSC 任务。近期 Zhou et al.（2024）提出的 TfPf 是一种无需训练、无需提示词的方法，能够在跨领域场景下达到与监督微调方法相当的表现；我们正是在这一框架基础上进一步提升性能，并将其扩展到 C2EC 任务。

### 9 结论
我们提出了 C2EC 任务，它是传统 CSC 的扩展，除了处理错字之外，还处理过去常被忽略的两类错误：多字和缺字。为了支持这一任务，我们通过整合并人工核验两个已有数据集，构建了一个专注于真实错误的 C2EC 数据集。同时，我们在 TfPf 方法基础上提出了一种无需训练的 C2EC 方法。实验表明，该方法在传统 CSC 和 C2EC 数据集上都显著优于 10-shot 上下文学习和 TfPf 基线，并且能够让小模型达到与参数规模接近 50 倍的大模型相竞争的表现。

### 局限性
我们也指出了若干未来需要改进的限制。首先，研究范围目前仅限于中文字符错误纠正，但我们认为经过适当修改后，该方法也可以应用到其他语言，以及语法错误纠正、句子简化等更复杂任务中。其次，本文主要评估零样本或少样本推理场景下的 LLM 表现；如果有充足的标注数据，如何有效利用这些数据进一步提升本文方法，是未来值得研究的问题。再次，受计算资源限制，我们没有在更大规模模型上测试该方法，但我们认为更大参数规模的模型也可能从本文方法中受益。最后，本文方法需要访问模型的概率分布，因此无法直接应用于很多只能通过 API 调用的强大闭源模型；不过，我们认为仍有可能利用 API 模型的输出结果来进一步提升性能。
